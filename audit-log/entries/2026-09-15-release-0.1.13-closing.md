## Context

Tag `v0.1.13` yang di-push sebelumnya (run `34969651284`) adalah annotated tag object `7818d28` whose target commit is `94ed145` (`chore: release v0.1.13`), yang **tidak** mencakup fix `8d5c8e0` (`fix: remove unused WebAssembly.Global that crashes Bun 1.4.0`). Fix tersebut dibuat setelah rilis, jadi binary di tag `v0.1.13` asli akan crash pada Bun 1.4.0.

Karena tag remote tidak bisa di-force-update (keputusan pemilik), digunakan tag retry `v0.1.13-1` di commit `0660719` (HEAD `main`, mencakup `8d5c8e0`).

Tiga run gagal sebelumnya karena `publish.yml` masih menggunakan regex tag lama (`^v[0-9]+\.[0-9]+\.[0-9]+$`). Perbaikan (PR #321) merelaksasi trigger ke `"v*"` / `"v*.*.*-*"` dan menambahkan `BASE_VERSION` fallback di awk untuk ekstraksi catatan rilis dari `CHANGES.md`.

## Tag Format Exception

Tag `v0.1.13-1` melanggar kanonik `vMAJOR.MINOR.PATCH`. GitHub Release kanonis `v0.1.13` tidak ada (`gh release view v0.1.13` → `release not found`). Pilihan yang diambil: catat pengecualian eksplisit. Lihat § Exception di bawah.

## Keputusan (Update 2026-09-15T15:20Z)

**Pilihan yang diambil**: Tetap menggunakan tag retry `v0.1.13-1`, catat sebagai exception terhadap kanonik `vMAJOR.MINOR.PATCH`. GitHub Release kanonis `v0.1.13` tidak dibuat.

**Alternatif yang dipertimbangkan**:

| Alternatif | Kelebihan | Kekurangan | Status |
| --- | --- | --- | --- |
| Force-update `v0.1.13` ke `0660719`, hapus `v0.1.13-1`, buat Release kanonik | Tag kanonik, Release kanonik, tidak membingungkan | Membutuhkan izin force-push tag; npm `0.1.13` sudah publish | **Tidak diambil** — pemilih tidak force-update |
| Buat GitHub Release untuk tag `v0.1.13` yang ada (tanpa force-push) | Release kanonik tanpa force-push | Tag `v0.1.13` menunjuk ke `94ed145` (tanpa fix `8d5c8e0`); binary di-upload dari `0660719` → Release menunjuk ke commit yang berbeda dari binary; binary dari workflow trigger `v0.1.13` akan crash pada Bun 1.4.0 | **Tidak diambil** — misleading dan unsafe |
| Tag retry `v0.1.13-1` (diambil) | Tidak perlu force-update; integritas history terjaga | Tag non-kanonik; Release kanonis `v0.1.13` tidak ada | **Diambil** — catat sebagai exception |

**Risiko**: Pengguna yang mencari `v0.1.13` di GitHub Releases tidak menemukannya (hanya `v0.1.13-1`). Mitigasi: `CHANGES.md` footer dan issue #315 sudah merujuk ke `v0.1.13-1`.

**Rekomendasi masa depan**: Jika tag remote `v0.1.13` bisa di-force-update tanpa risiko, lakukan migrasi ke tag kanonik. Tag `v0.1.13-1` bisa diurusnapada `v0.1.13` sudah benar.
